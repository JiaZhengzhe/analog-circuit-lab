你熟悉的是 H(s)、噪声密度、建立时间和管级失真；数字团队熟悉的是时钟沿、valid、队列和覆盖率。AFE 行为级模型就是这两种语言之间的合同：它不负责复刻每一伏特的物理过程，而负责让数字世界在正确的时间看到正确的后果——正确的码、正确的延迟、正确的饱和、正确的统计特性。

如果只记住五件事

  1. 先写契约，再写代码。单位、采样沿、延迟、复位、随机种子、精度容差，都要在模型之外写清楚。
  2. 在采样率上建模。RNM 是离散事件模型，不是把 SPICE 的变步长求解器塞进 always 块。
  3. 先推导差分方程。一阶用精确 ZOH，二阶用双线性 + 预畸变；系数要能追溯到 H(s)。
  4. real 是两态的。没有 X/Z；未知、无效、溢出必须用独立的 valid / flag 表达。
  5. 模型的价值在可验证性。能被 DC、阶跃、正弦、噪声和饱和测试反复证伪的模型，才是可交付的模型。

0导读：先建立正确的问题

很多 AFE 模型失败，不是因为 real 用错了，而是因为一开始就问错了问题：“怎么把电路搭出来？” 数字验证真正要问的是：“在数字引脚上，什么必须是对的？什么可以错？错多少仍然可接受？”

0.2 十条结论

本文的骨架
  1. 模型是合同，不是波形发生器。没有写清楚采样沿、延迟和复位语义的模型，数字端无法判断对错。
  2. 在采样率上推进状态。每个 posedge clk 只做一次“采样 → 计算 → 提交”；不要用极小的时间步去逼近连续积分。
  3. 连续系统先离散化。一阶 RC 用精确 ZOH，二阶滤波器用双线性 + 预畸变；先有差分方程，再有 always 块。
  4. 区分算法延迟与实现延迟。差分方程给出 y[n]；硬件寄存器、ADC 转换和流水线又增加 LAT 个周期。两者都要在契约里写清楚。
  5. real 没有 X/Z。未初始化是 0.0；未知、无效、过载必须用 valid、sat 等独立信号表达。
  6. 端口要显式声明为变量。不同工具对 input real 的 net/变量处理不一致；写 input var real 最稳。
  7. 计算用阻塞，提交用非阻塞。组合中间量用 =，跨时钟状态用 <=；不要在同一个沿依赖另一个 always 块刚写入的值。
  8. 损伤要独立、可标定、可关闭。噪声不是“加一个随机数”，而是有密度、带宽、积分方式和种子的物理量。
  9. 四域验证。DC 增益、阶跃/建立、幅频/相频、噪声/失真统计；任何一域没对齐，都不要交给 DV。
  10. 性能是功能的一部分。在采样率上算、预计算系数、关闭逐样本打印；一个跑不完的模型等于没有模型。

0.4 一条重要的边界：RNM 不是“低精度 SPICE”

RNM（Real Number Modeling）用实数表示电压/电流，但时间仍然是离散事件。它没有 KCL/KVL 求解器，也没有自适应时间步；它靠预先推导好的离散方程推进状态。这个限制不是缺陷，而是速度的来源。代价是：连续时间中那些“发生在两个采样点之间”的效应，必须被显式地建模成采样后的等效结果，或者被证明可以忽略。

连续时间  ── 采样/保持 ──▶  离散序列  ── 差分方程 ──▶  SV 状态
   H(s)                 x[n] = x(nTs)          y[n] = f(x, state)        always @(posedge clk)

所以本文的默认建模对象是采样率上的等效系统：如果 ADC 是 1 MS/s，就让模型以 1 MHz 推进；如果数字抽取滤波器也在待验证的 DUT 里，就把模型推进到调制器/抽取器输入的高速率。是否需要在模型内部过采样，只取决于一个问题：带外分量混叠回来后，是否会改变数字端看到的码？

1先定义“给数字验证的模型”

在写第一行 SystemVerilog 之前，先完成一份比代码更重要的东西：模型契约。它回答的是“数字端如何合法地使用这个模型”，而不是“这个模型内部有多像电路”。契约越早写，后期返工越少；尤其是延迟、复位和随机性这三件事，一旦数字环境按错误假设搭好，改模型就会牵动整个 testbench。

1.1 模型不是电路，是接口合同

一个 AFE RNM 的“正确”至少有三个维度：数值保真度（增益、带宽、噪声、失真）、时间保真度（采样沿、延迟、valid、吞吐）、可控性（参数、种子、故障注入、观测点）。三者缺一不可。只有数值对、延迟错的模型，会让 scoreboard 永远对不齐；只有时序对、噪声错的模型，会让算法组得出错误的 ENOB 结论。

1.3 延迟、valid 与吞吐：最容易被低估的三件事

在模拟域里，“输出”是一个连续波形；在数字域里，“输出”是一个带有效标记的事件。AFE 模型必须把三者分开定义：

  • 算法延迟：差分方程本身需要的延迟。例如 y[n] 依赖 x[n−1]，就至少有一个采样周期的记忆。
  • 实现延迟：ADC 转换、数字流水线、输出寄存器带来的周期数。它通常远大于算法延迟，而且数字端必须知道。
  • 吞吐：每多少个时钟产生一个有效样本。本文示例是 1 sample/clk；真实 AFE 可能是 1 sample/N clk，或者带 ready/valid 背压。

图 1-2 的时序契约可以写成三句话：在 posedge clk 采样 x[n]；经过 LAT 个周期后，adc_valid 与对应的 adc_data 同拍出现；enable=0 视为掉电：模拟状态与流水线立即清零，adc_valid 立即拉低；重新使能后从空状态开始，需要重新建立。scoreboard 必须按“第几个有效样本”而不是“第几个时钟”来对齐，否则一旦插入等待周期就会错位。

1.4 误差预算：先决定“错多少可以接受”

1.5 哪些东西可以不建模

“不建模”不是偷懒，是经过证明的省略
  • 晶体管级噪声相关性：除非在做 Chopper/相关双采样算法的极限验证，否则独立高斯噪声足够。
  • SAR 的逐位比较细节：除非数字端真的能看到 bit-trial 时序或需要验证 comparator metastability，否则用“采样 + 量化 + 固定延迟”更合适。
  • 电荷注入、时钟馈通、封装寄生：它们主要改变模拟建立/失调；如果最终只体现为几毫伏的固定误差，用参数化 offset 表示即可。
  • 电源网络的完整 RLC：如果 PSRR 在目标频段足够高，用“电源纹波 × PSRR”折算成输入误差，比搭一个电源网络更可控。
  • 所有 PVT 组合的连续仿真：用参数扫描 + 少量 SPICE 锚点，不要试图在 RNM 里复刻每个 corner 的器件物理。

2SystemVerilog 的最小必要子集

你不需要先成为 UVM 专家，才能写出好的 RNM。对 AFE 建模来说，真正高频使用的是：模块/端口、real 与 logic、参数、阻塞/非阻塞赋值、函数、数组、接口，以及少量断言。下面按“模拟工程师会踩的坑”来组织，而不是按语言手册的章节顺序。

2.1 事件驱动：时间不是连续流动的

在 SystemVerilog 中，仿真时间只在事件发生时推进。同一个时间点内部又分成多个区域：Active 区执行阻塞赋值，Inactive 区处理 #0，NBA 区提交非阻塞赋值，Observed/Reactive 区处理断言和并发进程。一个 always @(posedge clk) 块在 Active 区被唤醒；如果它用 <= 赋值，新值要到 NBA 区才可见。因此两个同时被唤醒的块，看到的可能是“旧值”。这不是仿真器的 bug，而是离散事件语义。

对 AFE 模型的直接结论是：在一个时钟沿内，先把本次采样需要的所有输入读进局部变量，再用非阻塞赋值提交状态。不要写“第一个 always 块更新 x，第二个 always 块立刻用新的 x”这种依赖执行顺序的代码。

2.2 一个最小但完整的模块骨架

snippet/ports.svsystemverilog
`timescale 1ns/1ps

module afe_chain #(
  parameter real VCM       = 0.9,
  parameter real LNA_GAIN  = 10.0,
  parameter int  ADC_BITS  = 12,
  parameter int  ADC_LATENCY = 3
)(
  input  logic                 clk,
  input  logic                 rst_n,
  input  logic                 enable,
  input  logic [1:0]           gain_sel,
  input  var real              vin_p,
  input  var real              vin_n,
  output logic [ADC_BITS-1:0]  adc_data,
  output logic                 adc_valid,
  output logic                 sat_flag,
  output var real              dbg_lna
);
  localparam real LSB = 1.8 / (1 << ADC_BITS);
  localparam int  LAT = (ADC_LATENCY < 1) ? 1 : ADC_LATENCY;

  real lna_state;
  logic [ADC_BITS-1:0] code_pipe [0:LAT];
  logic                valid_pipe[0:LAT];

  assign adc_valid = valid_pipe[LAT];

  always @(posedge clk) begin
    if (!rst_n) begin
      lna_state <= VCM;
      // ... clear all history and the digital pipeline ...
    end else if (enable) begin
      // sample -> compute -> commit
    end
  end
endmodule

这段骨架里有四个值得注意的选择：

  • input var real：端口的默认 net 规则与 real 的兼容性在不同工具/版本间并不完全一致：有的工具会把 input real 当成 real net 而报 invalid type for net，有的则自动当变量处理。显式写 var 可以消除这种歧义，交付代码不要依赖工具的宽容。
  • 参数用 real：物理量直接写 SI 单位（1.0e6 表示 1 MHz），避免在表达式里混用 µs 和 ns。
  • 输出既有数字码，也有 debug 实数：数字端用 adc_data/adc_valid；模拟工程师用 dbg_lna/dbg_aaf/dbg_pga 检查内部波形。debug 端口不应改变主路径行为。
  • 没有 wire 驱动的 real：所有实数状态都在 always 块里更新；端口是变量，不是 net。

2.4 always、阻塞与非阻塞：一条足够用的规则

snippet/race.svsystemverilog
// Two always blocks at the same edge: order is not a contract.
always @(posedge clk) begin
  a = b + 1;       // blocking: new a is visible immediately
  c = a + 1;       // this reads the NEW a
end

always @(posedge clk) begin
  a <= b + 1;      // nonblocking: commit in NBA region
  c <= a + 1;      // this reads the OLD a
end

// Rule for AFE state: compute with "=" in a local block,
// commit every state variable with "<=" at the end.

规则可以压缩成八个字：组合用等号，状态用箭头（= vs <=）。在时钟块内，所有跨时钟沿保持的变量（滤波器历史、流水线、计数器）用非阻塞；只在本次计算中使用的临时变量用阻塞。这样下一个时钟沿看到的是“上一沿提交的完整状态”，而不是执行到一半的中间值。

snippet/always_style.svsystemverilog
real diff, cm_err, lna_next;

// Pure combinational helper: inferred sensitivity.
always_comb begin
  diff   = vin_p - vin_n;
  cm_err = ((vin_p + vin_n) * 0.5 - VCM) / CMRR_LIN;
end

// Clocked state: prefer plain always for real arithmetic if the
// tool warns about always_ff / non-integral variables.
always @(posedge clk) begin
  if (!rst_n) begin
    lna_state <= VCM;
    valid_pipe <= '0;
  end else if (enable) begin
    lna_next   = VCM + LNA_A * (lna_state - VCM)
                     + (1.0 - LNA_A) * LNA_GAIN * (diff + cm_err);
    lna_state <= lna_next;
  end
end

always_comb 会自动推断敏感列表，适合纯组合的辅助函数；但它对 real 变量赋值时，部分工具会给出“不可综合”的警告。行为模型本来就不综合，这个警告可以接受；如果团队的 lint 流程不允许，改用 always @* 或直接把表达式写进时钟块。不要为了让警告消失，把实数运算强行改成定点——那会引入新的量化误差。

2.5 timescale、单位与“看不见的 1000 倍”

文件开头写 `timescale 1ns/1ps，则 #1 是 1 ns，$realtime 返回以 ns 为单位的时间值。AFE 模型内部通常不需要 delay，但 testbench 会用；如果参数用秒、时间用 ns，就必须显式乘 1e-9。作者见过最隐蔽的 bug 之一，是把 1e6 当成“1 µs”的代换，结果滤波器截止频率差了 1000 倍，而波形“看起来只是有点慢”。

建议

模型内部只使用 SI 单位；所有时间参数写成 ..._S（秒），所有频率写成 ..._HZ。testbench 的时间推进用 timescale，不把“µs”混进模型参数。这样任何人读代码都不需要猜单位。

2.6 函数、package 与随机数：把物理写在一处

把钳位、dB 转换、增益译码、噪声生成放进 package 或 function automatic，主模型只负责状态推进。函数不要读写全局状态（随机数函数例外，它必须推进 seed），否则仿真结果会依赖调用顺序。

snippet/gauss.svsystemverilog
function automatic real gauss();
  int unsigned r1, r2;
  real u1, u2;

  r1 = $urandom(rng_state);
  r2 = $urandom(rng_state);
  u1 = (r1 + 1.0) / 4294967297.0;  // strictly in (0,1)
  u2 = r2 / 4294967296.0;          // [0,1)

  gauss = $sqrt(-2.0 * $ln(u1)) * $cos(2.0 * PI * u2);
endfunction

// Call only when the impairment is enabled, otherwise the random
// sequence changes when you toggle an unrelated parameter.

高斯噪声用 Box–Muller：两个独立均匀分布 → 两个独立标准正态。这里有两个细节：u1 必须严格大于 0，否则 $ln(0) 会得到负无穷；$urandom(seed) 会推进命名 seed，因此同一个 seed + 同一调用顺序可以复现。不要用 $random 直接除以 2^31 当高斯用——它是均匀分布，不是正态。

随机数还有一个验证层面的要求：seed 必须是参数或 plusarg，不能硬编码在函数里。回归时需要“同一种子复现失败、不同种子扫描覆盖”，而不是每次跑出不同的波形却无法重放。

2.7 数组、结构体与接口

滤波器历史、流水线、码流缓存都用数组。SystemVerilog 支持定长数组、动态数组和队列；RNM 里最常用的是定长数组（状态数固定）和队列（scoreboard 按到达顺序比较）。例如：

snippet/arrays.svsystemverilog
// Fixed history for a direct-form biquad.
real x1, x2, y1, y2;

// Pipeline: valid travels with data, one entry per cycle.
logic [11:0] code_pipe  [0:LAT];
logic        valid_pipe [0:LAT];

// Queue for a scoreboard: expected transactions in arrival order.
afe_txn expected[$];

initial begin
  x1 = VCM; x2 = VCM;
  y1 = VCM; y2 = VCM;
end

接口（interface）适合把“模拟引脚 + 数字引脚 + 时钟”打包，但不要把模型内部状态放进去。一个实用的划分是：interface 只放引脚和采样时钟；transaction 放一次观测；model 内部状态保持私有。这样 monitor 可以在不改模型的情况下替换采样策略。

2.8 断言与覆盖率：让模型自己报告“我错了”

行为模型最怕“安静地错”。至少加三类检查：valid 与 data 同拍、码值在合法范围、复位/使能后第一个 valid 的延迟符合契约。实数比较不要用 ==，用容差：abs(a-b) <= tol。

snippet/assert_real.svsystemverilog
function automatic real abs_real(input real x);
  abs_real = (x < 0.0) ? -x : x;
endfunction

always @(negedge clk) begin
  if (rst_n && adc_valid) begin
    if (adc_data > 12'hFFF)
      $error("ADC code out of range: %0d", adc_data);

覆盖率方面，很多工具对“直接对 real 做 coverpoint”支持不一致。稳妥做法是先把 real 映射成整数 bin，再覆盖：

int amp_bin, freq_bin;

// Map continuous quantities to stable integer bins first.
always @(posedge clk) begin
  amp_bin  = (amp_v * 8.0 / VREF > 7.0) ? 7 :
             (amp_v <= 0.0) ? 0 : $rtoi(amp_v * 8.0 / VREF);
  freq_bin = (freq_hz < 1e3) ? 0 :
             (freq_hz < 10e3) ? 1 : 2;
end

covergroup cg_frontend @(posedge clk);
  cp_amp:  coverpoint amp_bin  { bins b[] = {[0:7]}; }
  cp_freq: coverpoint freq_bin { bins b[] = {[0:2]}; }
  cx: cross cp_amp, cp_freq;
endgroup

2.9 与 UVM 的接口：只需要四件事

你不需要为了 AFE 模型重学一遍 UVM。最小集成只需要：

  1. Transaction：带 real 字段（输入幅度/频率、观测到的模拟节点）和数字字段（code、valid、sat）。real 字段可以直接放；打印/复制宏对 real 的支持依 UVM 版本而定，必要时自己写 convert2string()。
  2. Driver：把 transaction 转成波形，在 negedge clk 或 clocking block 中更新模拟输入，避免与 DUT 的 posedge 竞争。
  3. Monitor：在 negedge clk 采样 DUT 输出，发布带时间戳的 transaction；不要在 posedge 的 Active 区读非阻塞输出。
  4. Scoreboard：按 valid 计数和 latency 对齐，而不是按绝对时间；对数字码做精确/±1 LSB 比较，对噪声统计做批量指标比较。
snippet/uvm_monitor.svsystemverilog
class afe_monitor extends uvm_monitor;
  `uvm_component_utils(afe_monitor)
  virtual afe_if vif;
  uvm_analysis_port #(afe_txn) ap;

  function new(string name, uvm_component parent);
    super.new(name, parent);
    ap = new("ap", this);
  endfunction

  task run_phase(uvm_phase phase);
    afe_txn t;
    forever begin
      @(negedge vif.clk);          // stable, after NBA
      if (vif.rst_n && vif.adc_valid) begin
        t = afe_txn::type_id::create("t");
        t.code  = vif.adc_data;
        t.sat   = vif.sat_flag;
        t.gain  = vif.gain_sel;
        t.time  = $realtime;
        ap.write(t);
      end
    end
  endtask
endclass

如果团队已经有 UVM 寄存器模型、SPI VIP 或时钟/复位 agent，优先复用；AFE 模型只提供“模拟波形 + 数字引脚”，不要把整个验证环境重新发明一遍。

3从 s 域到可执行差分方程

这一章是整篇教程的数学核心。目标不是证明数值分析定理，而是建立一条可重复的路径：给定 H(s) 和采样率，得到稳定的 H(z)，再写成每个时钟沿执行一次的赋值。只要这条路径走对，后面的 AFE 分级只是“把不同的 H(s) 接起来”。

3.1 先选采样率：模型的时间分辨率从哪里来

RNM 的采样率不一定是 ADC 的采样率，但它必须至少覆盖你要保留的最高频率。三条实用规则：

  1. 只关心基带码流：模型可以按 ADC 输出率推进。前提是输入已经被抗混叠滤波器带限，或者你只注入带限测试音。
  2. 需要观察 AAF 的阻带/混叠：把模型推进到高于 ADC 率的过采样率（例如 8×），在模型内部做模拟滤波，再按 ADC 时刻抽样；否则离散模型无法表示“采样前的高频分量”。
  3. ΔΣ / 数字抽取在 DUT 内：模型必须推进到调制器速率；抽取滤波器是数字 DUT 的一部分，不能提前替它抽掉。
混叠不是“模型误差”，是采样系统的真实行为

如果输入在 fs/2 以上有能量，而 AAF 抑制不够，这些能量会折返到基带并改变码流。一个只在 fs 上推进的模型，无法区分“基带有一个 10 kHz 音”和“带外有一个 990 kHz 音混叠到 10 kHz”。要么在激励端带限，要么提高模型采样率；不要用“反正是行为模型”来掩盖这个物理事实。

3.2 一阶 RC：精确 ZOH 离散化

考虑一阶低通

H(s) = 11 + sτ,　τ = RC = 12πfc
(3-1)

对应的微分方程是 τ · dy/dt + y = x。假设输入在采样 interval 内保持为常数 x[n]（零阶保持），从 t=nTs 到 t=(n+1)Ts 解这个一阶线性方程，得到

y[n+1] = a · y[n] + (1 − a) · x[n],　a = e−Ts/τ
(3-2)
精确 ZOH 离散化；对任意 Ts 都稳定（0 < a < 1），且 DC 增益严格为 1

推导只用了“区间内输入不变”这一条假设，没有做任何差分近似。它的频响在低频与连续系统一致，在高频会因 ZOH 的 sinc 包络而滚降；对于 fc ≪ fs 的 AFE，这个差异远小于工艺容差。实现时把 a 预计算成 localparam real，每次采样只做一次乘加。

阶跃响应是 y(t) = A(1 − e−t/τ)。要在 N 位系统中建立到 0.5 LSB，需要

ε = 12N+1,　ts = τ · ln(2N+1) = (N+1) ln2 · τ ≈ 0.693(N+1)τ
(3-3)
12-bit：约 9.0τ；16-bit：约 11.8τ。只适用于一阶、线性、无压摆限制的建立

3.3 二阶滤波器：双线性变换与预畸变

双线性变换用梯形积分把 s 平面映射到 z 平面：

s ← 2Ts · 1 − z−11 + z−1
(3-4)
把左半 s 平面一一映射到单位圆内，因此稳定系统离散后仍稳定

直接代入会把连续频率 f 压到数字频率，产生“频率畸变”：低频尚可，接近 fs/2 时误差很大。解决办法是预畸变：先选一个希望精确匹配的频率 fc，令

K = tan(π · fc / fs)
(3-5)
保证数字滤波器在 fc 处的响应与连续原型一致；fc 必须小于 fs/2

对二阶 Butterworth 低通

H(s) = ωc2s2 + √2 ωcs + ωc2
(3-6)

代入并归一化，得到直接 I 型系数

D = 1 + √2K + K2
b0 = K2/D,　b1 = 2K2/D,　b2 = K2/D
a1 = 2(K2 − 1)/D,　a2 = (1 − √2K + K2)/D
(3-7)
y[n] = b0x[n] + b1x[n−1] + b2x[n−2] − a1y[n−1] − a2y[n−2]
(3-8)

注意符号：分母写成 1 + a1z−1 + a2z−2，所以差分方程里是“减 a1、减 a2”。如果代码里写成“加”，在 a1 为负时看起来也能跑，但极点位置会错，阶跃响应会振铃甚至发散。这类错误很难从波形一眼看出，必须用 DC 增益和阶跃/AC 响应验证。

示例系数（fc = 100 kHz, fs = 1 MHz）

K = 0.32492, D = 1.56508, b0 = b2 = 0.067455, b1 = 0.13491, a1 = −1.14298, a2 = 0.41282。DC 增益 (b0+b1+b2)/(1+a1+a2) = 1.000。这些数就是示例代码里直接使用的系数。

3.5 数值实现：直接 I 型、转置型与级联

示例使用直接 I 型，因为它的状态 x1,x2,y1,y2 与差分方程一一对应，最容易教学和调试。高阶滤波器不要直接展开成一个高阶差分方程：系数的动态范围会变大，有限精度下容易不稳定。工程上更稳的做法是分解成多个二阶节（biquad）级联，每节独立检查 DC 增益、极点和输出范围。

对 64-bit real，12–16 bit 的音频/传感器 AFE 通常不需要担心系数精度；但三种情况要特别小心：

  • 极低频、极高 Q：极点贴近单位圆，系数的微小误差会显著移动极点。
  • fc 接近 fs/2：tan(π fc/fs) 很大，预畸变后系数动态范围变大。
  • 用 shortreal 存系数：24-bit 尾数在深零极点下可能不够；除非做过误差扫描，否则系数用 real。

3.6 算法延迟与实现延迟：不要把两者混为一谈

差分方程 y[n] 用的是当前输入 x[n]；但在真实 ADC 中，采样、转换、输出寄存器会额外增加延迟。建模时建议把两者分开：

  • 滤波器状态延迟：由差分方程决定，体现在 x1/x2/y1/y2 上。
  • 输出流水线延迟：由 ADC_LATENCY 决定，只延迟 valid/data，不改变模拟状态。

这样做的优点是：改变 ADC 延迟不会改变滤波器的频率响应，scoreboard 也只需要调整一个参数。反过来，如果把延迟塞进滤波器系数里，任何时序变化都会污染模拟指标。

3.7 积分器与 ΔΣ：什么时候需要过采样

积分器是 ΔΣ 调制器、电荷泵、基线漂移模型的核心。连续积分器 H(s) = 1/(sτ) 的双线性形式是

y[n] = y[n−1] + Ts2τ(x[n] + x[n−1])
(3-9)

对一阶 ΔΣ 调制器，一个常用的离散模型是：

snippet/delta_sigma.svsystemverilog
// First-order, single-bit delta-sigma (illustrative).
// The bitstream must be processed at the modulator rate.
real integ;
logic bit_out;
logic bit_prev;

always @(posedge clk) begin
  if (!rst_n) begin
    integ    <= 0.0;
    bit_prev <= 1'b0;
  end else begin
    // Integrate the error between input and fed-back output.
    integ    <= integ + x_in - (bit_prev ? 1.0 : -1.0);
    bit_out  <= (integ >= 0.0);
    bit_prev <= bit_out;
  end
end

这类模型的输出是高速 1-bit 码流，不是最终 PCM 码。若数字抽取滤波器在 DUT 内，模型必须推进到调制器速率（OSR × 输出率），把码流交给 DUT；若只想验证最终音频指标，可以在模型内部实现一个理想抽取器，直接输出 PCM。两种做法的验证目标不同，不能混用。

4AFE 链路的逐级建模

现在把数学映射到具体电路。下面以一个单电源、差分输入、单端输出的传感器 AFE 为参考：输入共模 0.9 V，电源 1.8 V，LNA 增益 10，AAF 100 kHz，PGA 1–8 倍，12-bit ADC，1 MS/s。实际 AFE 可能全差分、电流输入或带 Chopper，但每一级的“输入—传递—非理想—观测”结构是一样的。

4.1 输入网络与传感器：先决定“源”的等效电路

传感器对 AFE 来说不是理想电压源。至少要有：

  • 差模源 vd：你要放大的信号。
  • 共模 vcm：决定输入级工作点，也通过 CMRR 泄漏到输出。
  • 源阻抗 Rs：与输入电容/输入电流作用，形成低通和噪声。
  • 直流失调 Vos：电极/电桥/传感器零点，可能远大于信号。

如果源阻抗和输入电容形成的极点远高于信号带宽，可以只把 Rs 折算成热噪声，不必建完整的 RC 网络。反过来，如果传感器是高阻（例如 pH 电极、光电二极管），输入电容和输入偏置电流会直接改变带宽和失调，必须显式建模。

vn,Rs = √(4kTRs · Δf)
(4-1)
k = 1.380649×10−23 J/K；300 K 时 4kT ≈ 1.657×10−20 J

4.2 LNA：增益、带宽、共模与削顶

把 LNA 建模成“围绕输出共模 VCM 的一阶低通 + 增益 + 钳位”既简单又足够回答大多数 DV 问题：

vLNA(s) = VCM + G · vd(s)1 + s/ωLNA + G · vcm − VCMCMRRlin + G · Vos
(4-2)
第一项是输出共模；第二项是差模信号的一阶响应；第三项是共模泄漏；第四项是输入失调

对应的离散形式就是 3.2 节的 ZOH：

examples/afe_chain.sv:185–194systemverilog
      // 2. LNA: gain, first-order bandwidth, rail clipping.
      //    Exact ZOH discretization of 1/(1 + s*tau), tau = 1/(2*pi*fc).
      //----------------------------------------------------------------------
      // VCM is the output common mode; the signal path is AC-coupled around it.
      lna_out = VCM + LNA_A * (lna_state - VCM)
                     + (1.0 - LNA_A) * LNA_GAIN * x_in;

      sat_lna = (lna_out > VDD) || (lna_out < 0.0);
      lna_out = clamp_real(lna_out, 0.0, VDD);

两个容易犯的建模错误：

  1. 忘了输出共模。只写 lna_out = a*state + (1-a)*G*x，在零输入时输出会收敛到 0 V，而不是 VCM；ADC 码会从 2048 变成 0，后续所有测试都“看起来饱和”。
  2. 把 LNA 当理想增益。没有钳位时，大输入会产生超过电源的码；有了钳位但不设 sat，数字端不知道这是削顶而不是真实信号。两者都要有。

LNA 的噪声通常以输入参考噪声密度给出。若只关心基带，用 vn = NSD · √ENBW 把密度积分成 RMS；若在模型里逐样本注入白噪声，则每个样本的标准差是 NSD · √(fs/2)。两者的区别见 4.6 节。

4.3 AAF：为什么二阶 Butterworth 是一个好默认

AAF 的任务是抑制 fs/2 以上的分量，防止混叠。Butterworth 的优点是通带平坦、相位相对温和、系数容易手算；缺点是阻带滚降只有 20n dB/decade，对强带外干扰可能需要更高阶或椭圆滤波器。对行为模型来说，先用二阶 Butterworth 建立基线，再用实测/SPICE 的 S21 替换系数，通常比一上来就搭一个高阶椭圆滤波器更可控。

examples/afe_chain.sv:196–205systemverilog
      // 3. Anti-alias filter: 2nd-order Butterworth, bilinear with prewarp.
      //    y[n] = b0*x[n] + b1*x[n-1] + b2*x[n-2]
      //           - a1*y[n-1] - a2*y[n-2]
      //----------------------------------------------------------------------
      aaf_out = AAF_B0 * lna_out + AAF_B1 * x1 + AAF_B2 * x2
              - AAF_A1 * y1      - AAF_A2 * y2;

      aaf_out = clamp_real(aaf_out, 0.0, VDD);

检查 AAF 模型是否正确的顺序：

  1. DC 增益：输入恒定 0.9 V，输出应回到 0.9 V（允许启动瞬态）。
  2. 截止频率：扫频或扫几个频点，确认 −3 dB 在 fc 附近；注意预畸变只保证 fc 一个点精确。
  3. 阶跃：二阶 Butterworth 的阶跃过冲约 4.3%（连续原型）；如果模型过冲很大或振铃不止，先查 a1 符号和极点。
  4. 带外抑制：在 0.4–0.5 fs 附近注入单音，确认混叠后的幅度符合预期。

4.4 PGA：增益、共模与“放大绝对电压”的陷阱

PGA 通常是单电源、围绕某个输出共模工作的。正确的关系是“放大偏离共模的量”，而不是“放大整个电压”：

vPGA = VCM + GPGA · (vAAF − VCM)
(4-3)
真实踩坑：PGA 把共模也放大了

示例模型最初写成 pga_out = gain * aaf_out。增益为 1 时一切正常；切到 2× 后，0.9 V 的共模变成 1.8 V，信号正半周直接削顶，测出来的 SNR 只有 34 dB。修正为 VCM + gain*(aaf_out - VCM) 后，2× 档的码范围回到 230…3867，SNR 恢复到 70.1 dB。这个 bug 在只测 1× 档时完全看不出来，所以增益档必须逐个验证。

PGA 的其它非理想项：

  • 增益误差/漂移：用 G_nom * (1 + gain_err_ppm*1e-6)，并允许按温度/寄存器更新。
  • 建立时间：增益切换后，PGA 输出不是瞬间到位；如果数字端在切换后立即采样，会得到旧增益的码。模型应把“增益更新”限制在采样边界，并可选加一阶建立。
  • 输出摆幅：PGA 输出范围通常小于电源轨；用独立的 PGA_MIN/PGA_MAX，不要直接复用 LNA 的轨到轨钳位。

4.5 采样/保持与 ADC：量化只是第一层

理想采样保持的输出是 vsh[n] = vin(nTs)。在 RNM 里，这一步通常隐含在“每个 posedge 读一次输入”中；如果要建模孔径抖动，就在采样时刻加一个与输入斜率成正比的误差：

ej[n] ≈ dvindtt=nTs · Δtn,　Δtn ~ N(0, σt2)
(4-4)

对满幅正弦 v = Asin(2πft)，只考虑抖动时的 SNR 是

SNRj = −20 log10(2πfσt)
(4-5)
与幅度无关；10 kHz + 1 ps 约 144 dB，100 MHz + 1 ps 只有约 4 dB

这解释了为什么低频 AFE 默认可以关掉抖动，而高速 ADC 必须打开。注意公式假设“满幅正弦 + 只有抖动”，实际还要与量化、热噪声按功率合成。

量化器把连续电压映射成 N-bit 码。对单极性、0…VREF 的 offset-binary ADC：

code = clamp( round( vin/VREF · 2N ), 0, 2N − 1 )
(4-6)

如果输入是双极性、以 VREF/2 为中心，则先做 vin + VREF/2 的平移，或直接输出 two’s complement。关键是在契约里写清楚编码：offset binary、two’s complement、还是 sign-magnitude；DV 的 scoreboard 会按这个约定解码。

图 4-2 用 4-bit 示例说明 INL/DNL 的关系：DNL 是每个码宽相对 1 LSB 的偏差，INL 是转换电平相对理想直线的偏差（通常按端点或最佳拟合线定义）。对行为模型，有两种做法：

  • 多项式弓形：用 INL(x) = k·x(1−x) 之类的平滑形状，参数少、可扫；适合“有 INL 但不关心具体码”的场景。
  • LUT：用实测/SPICE 的每个码的转换电平，逐码修正；适合做 DNL、缺失码、码密度测试。LUT 更真实，但需要标定数据，且仿真成本更高。

如果只做 DV 的功能验证，通常不需要逐码 LUT；一个可开关的 INL 弓形 + 钳位就足够证明“校准算法能吃掉这个误差”。如果算法团队要评估 INL 对 ENOB 的影响，再升级到 LUT。

4.6 噪声：密度、带宽、积分与注入点

噪声是 AFE 模型里最容易“看起来有、其实不对”的部分。四个问题必须先回答：

  1. 参考点在哪里？输入参考（RTI）还是输出参考（RTO）？两者相差一个增益。
  2. 单边还是双边？数据手册通常给单边 PSD（V/√Hz）；离散白噪声的方差要用 NSD2·fs/2。
  3. 积分到多大带宽？用信号带宽、滤波器 ENBW，还是 fs/2？三者差别很大。
  4. 噪声在滤波器前还是后注入？前注入会被滤波器和增益整形；后注入是等效输出噪声。

一阶 RC 的等效噪声带宽是 ENBW = (π/2)fc = 1/(4RC)，因此电阻热噪声积分后得到经典的 kT/C：

vn,rms2 = 4kTR · 14RC = kTC
(4-7)
300 K、10 pF：约 20.3 µV rms；1 pF：约 64.3 µV rms

多级级联时用 Friis 公式把后级噪声除以之前的总增益：

vn,in2 = vn,12 + vn,22G12 + vn,32G12G22 + …
(4-8)

图 4-3 的左图是示例在 2× 增益下、折算到 ADC 输入端的噪声预算：热噪声约 121 µV rms，量化约 128 µV rms，RSS 后约 176 µV rms。右图说明一个常见的误解：提高 PGA 增益并不必然提高 SNR。在未削顶时，信号和输入参考热噪声一起被放大，热噪声的 SNR 不变；但量化噪声相对信号变小，所以总 SNR 会改善。到了 4×，输出削顶，SNR 反而崩到 34 dB。增益选择是“用满 ADC 量程”和“不要削顶”之间的折中，不是越大越好。

4.7 线性度：先钳位，再多项式

如果 AFE 的输入接近满幅，最先出现的非线性通常不是三阶，而是削顶。所以建模顺序应该是：

  1. 输出摆幅钳位（必须）。
  2. 可选的软压缩（tanh 或分段线性），让削顶不是硬拐角。
  3. 可选的二阶/三阶多项式，用于 HD2/HD3、IIP3 的近线性区。

三阶多项式 y = a1x + a2x2 + a3x3 的两个常用结论：

HD3 ≈ 14 · a3a1 · A2,　IIP3 = √( 4a13|a3| )
(4-9)
IIP3 是输入参考的两音等幅交点；HD3 是单音三阶谐波与基波的幅度比

对 DV 来说，线性度通常不是逐样本检查项，而是“跑一个双音/单音测试，看 FFT 的 SFDR/THD 是否落在预算内”。所以多项式参数应该能从 bench 的 IP3/P1dB 反推，而不是随手调一个“看起来像”的系数。

4.8 共模、电源与参考：三个“慢”但重要的输入

CMRR：把共模变化折算成差模误差。若 CMRRdB 已知，则

vd,err = vcm − VCM,nom10CMRRdB/20
(4-10)

PSRR：把电源纹波折算到输入参考。若 PSRRdB 定义为“电源纹波 / 输入参考误差”的比值，则输入参考误差为 vripple/10PSRR/20。注意 PSRR 随频率下降，低频 80 dB 不代表 1 MHz 还有 80 dB；如果 DV 只关心 DC/低频，可以用常数；如果关心开关电源纹波，至少给一个一阶滚降。

参考噪声：ADC 的输出码正比于 vin/VREF，所以参考噪声表现为增益调制。灵敏度是

∂code∂VREF = − vin · 2NVREF2
(4-11)

对 12-bit、1.8 V、0.9 V 输入，10 µV rms 的参考噪声只造成约 0.01 LSB 的码抖动，可以忽略；但对 16–18 bit 或接近满幅的输入，它可能进入预算。不要因为“参考是直流的”就默认它没有噪声。

4.9 数字控制、寄存器与故障注入

AFE 不只是模拟链，它还有 enable、增益档、掉电、校准寄存器、SPI/I²C 接口、过载标志。对 DV 来说，这些数字行为往往比模拟细节更重要。建模原则：

  • 更新边界：增益/模式在采样沿或帧边界生效；不要在任意时刻改变，否则会产生不可复现的中间态。
  • 读回：寄存器读回值应与写入一致；只读状态位（valid、sat、fault）不能被写。
  • 故障注入：提供参数或 plusarg 控制的“卡码、丢帧、错误 CRC、错误增益、过载”，并保证可重复。
  • 复位：区分“数字复位”（清流水线/寄存器）和“模拟掉电”（清滤波器/偏置）；两者的恢复时间不同。

5.3 参数与系数：把推导固化在编译期

所有能从参数算出来的东西都在 localparam 里算完。这样做的原因不是“优雅”，而是性能：在 1 MS/s、数千万样本的回归里，每个样本多做一次 $tan 或 $exp，都会变成可观的成本。

examples/afe_chain.sv:57–75systemverilog
  // Derived constants.  Everything that can be precomputed is precomputed:
  // real arithmetic inside the clocked process is the dominant cost.
  //--------------------------------------------------------------------------
  localparam real LSB        = VREF / (1 << ADC_BITS);
  localparam int  MAX_CODE   = (1 << ADC_BITS) - 1;
  localparam int  LAT        = (ADC_LATENCY < 1) ? 1 : ADC_LATENCY;

  localparam real LNA_A      = $exp(-2.0 * PI * LNA_BW_HZ / FS_HZ);
  localparam real AAF_K      = $tan(PI * AAF_FC_HZ / FS_HZ);
  localparam real AAF_D      = 1.0 + 1.4142135623730951 * AAF_K + AAF_K * AAF_K;
  localparam real AAF_B0     = AAF_K * AAF_K / AAF_D;
  localparam real AAF_B1     = 2.0 * AAF_B0;
  localparam real AAF_B2     = AAF_B0;
  localparam real AAF_A1     = 2.0 * (AAF_K * AAF_K - 1.0) / AAF_D;
  localparam real AAF_A2     = (1.0 - 1.4142135623730951 * AAF_K + AAF_K * AAF_K) / AAF_D;

  localparam real NOISE_SIGMA = NOISE_DENSITY * $sqrt(FS_HZ / 2.0);
  localparam real CMRR_LIN    = 10.0 ** (CMRR_DB / 20.0);
  localparam real FULL_SCALE  = 1 << ADC_BITS;

这里有三个设计决定值得说明：

  • LNA_A = exp(−2π·fc/fs) 是精确 ZOH 系数；它把“连续时间一阶极点”直接映到单位圆内。
  • AAF_K = tan(π·fc/fs) 是预畸变；AAF_D 是归一化分母。所有系数都是一次性计算。
  • NOISE_SIGMA = NSD·√(fs/2)：这是离散白噪声每个样本的标准差。注意它不是 NSD·√ENBW；后者是滤波后的 RMS，两者不能混用。

5.4 模拟链：输入、LNA、AAF、PGA、ADC

主模型每个时钟沿执行一次完整的“采样 → 计算 → 提交”。下面从 LNA 开始，省略了参数声明和流水线，完整上下文见代码文件。

examples/afe_chain.sv:185–204systemverilog
      // 2. LNA: gain, first-order bandwidth, rail clipping.
      //    Exact ZOH discretization of 1/(1 + s*tau), tau = 1/(2*pi*fc).
      //----------------------------------------------------------------------
      // VCM is the output common mode; the signal path is AC-coupled around it.
      lna_out = VCM + LNA_A * (lna_state - VCM)
                     + (1.0 - LNA_A) * LNA_GAIN * x_in;

      sat_lna = (lna_out > VDD) || (lna_out < 0.0);
      lna_out = clamp_real(lna_out, 0.0, VDD);

      //----------------------------------------------------------------------
      // 3. Anti-alias filter: 2nd-order Butterworth, bilinear with prewarp.
      //    y[n] = b0*x[n] + b1*x[n-1] + b2*x[n-2]
      //           - a1*y[n-1] - a2*y[n-2]
      //----------------------------------------------------------------------
      aaf_out = AAF_B0 * lna_out + AAF_B1 * x1 + AAF_B2 * x2
              - AAF_A1 * y1      - AAF_A2 * y2;

      sat_aaf = (aaf_out > VDD) || (aaf_out < 0.0);
      aaf_out = clamp_real(aaf_out, 0.0, VDD);

PGA 与 ADC 段是另一个关键点：PGA 围绕 VCM 放大，ADC 输入先钳位再量化；sat_now 汇总 LNA/AAF/ADC 的削顶事件，随后与数据一起进流水线。这样数字端看到的 sat_flag 与对应样本严格同拍。

examples/afe_chain.sv:207–247systemverilog

      //----------------------------------------------------------------------
      gain_now = PGA_GAIN * gain_from_sel(gain_sel);
      // The PGA is single-supply: it amplifies the deviation from VCM, not
      // the absolute voltage.  Otherwise the output common mode would move
      // with gain and the ADC would saturate for a purely differential input.
      pga_out  = VCM + gain_now * (aaf_out - VCM);

      // 5. Reference noise and quantization.  Offset-binary output:
      //    code 0 = 0 V, code 2^N-1 = VREF (within one LSB).
      //----------------------------------------------------------------------
      vref_eff = VREF;
      if (VREF_NOISE_RMS > 0.0)
        vref_eff = VREF + VREF_NOISE_RMS * gauss();

      code_ideal = $rtoi((pga_out / vref_eff) * FULL_SCALE + 0.5);
      if (code_ideal < 0)
        code_ideal = 0;
      else if (code_ideal > MAX_CODE)
        code_ideal = MAX_CODE;

      code = code_ideal;

      // Optional static INL bow.  It is a shape, not a substitute for
      // measured INL data; replace this with a LUT in a real project.
      if (INL_LSB != 0.0) begin

        code     = code + inl_code;
        if (code < 0)
          code = 0;
        else if (code > MAX_CODE)
          code = MAX_CODE;
      end

5.6 Testbench：相干采样、negedge 驱动、negedge 采样

FFT 的质量取决于采样是否相干。示例取 N = 4096、M = 41，信号频率 fin = (M/N)·fs = 10009.765625 Hz。这样信号正好落在第 41 个 FFT bin，不需要窗函数；如果频率不是整数 bin，必须加窗并做泄漏修正，否则 SNR 会被泄漏污染。

examples/tb_afe_sine.sv:76–111systemverilog

    @(negedge clk);
    rst_n = 1'b1;

    // Drive on the falling edge; the DUT samples on the next rising edge.
    forever begin
      @(negedge clk);
      vin_p = VCM + AMP * $sin(2.0 * PI * M * n / N);
      vin_n = VCM;
      n = (n + 1) % N;
    end
  end

  // Sample the DUT outputs on the falling edge, after the active edge has
  // settled.  This avoids the classic testbench race at posedge clk.
  always @(negedge clk) begin
    if (rst_n && adc_valid) begin
      if (got >= WARM && got < WARM + N) begin
        $fdisplay(fd, "%0d,%0d,%0d,%0d", got - WARM, adc_data, adc_valid, sat_flag);
        if (sat_flag)
          sat_count = sat_count + 1;
      end
      got = got + 1;

      if (got == WARM + N) begin
        $fclose(fd);
        $display("DONE: N=%0d M=%0d FIN=%f Hz", N, M, FIN);
        $display("     valid=%0d sat_in_window=%0d last_code=%0d", got, sat_count, adc_data);
        $finish;
      end
    end
  end

两个“反直觉但重要”的细节：

  • 驱动在 negedge，采样在 posedge。这样输入在 DUT 采样沿之前已经稳定，避免 testbench 与 DUT 在同一沿竞争。
  • Monitor 也在 negedge 读取。DUT 的输出用非阻塞赋值在 posedge 的 NBA 区更新；如果在 posedge 的 Active 区读，可能读到上一拍。negedge 读取的是稳定后的结果。

采集时丢掉前 512 个有效样本，等滤波器瞬态和流水线排空；然后收 4096 个样本。开始采集的绝对时间不重要，重要的是按 valid 计数，而不是按仿真时间硬编码。

5.8 阶跃与建立：19 µs 到 0.5 LSB

阶跃测试把输入从 0.9 V 跳到 0.94 V（40 mV），PGA 2× 后输出从 0.9 V 跳到 1.7 V。模型输出约有 4.2% 的过冲，这是二阶 Butterworth 的典型行为；从阶跃到误差进入 ±0.5 LSB（约 0.22 mV）用了 19.0 µs。一阶近似 (N+1)ln2·τ 对 12-bit 给出约 9τ ≈ 14.3 µs（τ = 1/(2π·100 kHz) = 1.59 µs），实测更慢，因为链路里还有一个 LNA 极点和二阶滤波器的相位。

这个结果对 DV 的直接意义是：如果数字端在增益切换后只等 10 µs 就开始采样，得到的码可能还在建立过程中；如果算法按“理想阶跃”做校准，会把建立误差当成增益误差。模型应该把“增益切换 → 建立 → 有效样本”的时间写进契约，而不是只给一个稳态增益。

5.9 复现实验与修改参数

想验证自己的理解，建议按下面顺序改参数，每改一次只观察一个指标：

  • 把 LNA_BW_HZ 从 200 kHz 改成 20 kHz：观察 10 kHz 信号的幅度/相位变化，以及阶跃建立变慢。检查 DC 增益是否仍为 1。
  • 把 AAF_FC_HZ 改成 30 kHz：观察 10 kHz 附近的衰减和群延迟；如果 fc/fs 变大，检查预畸变后系数是否仍稳定。
  • 把 NOISE_DENSITY 改成 100 nV/√Hz：观察 SNR 是否按平方根规律下降；确认不是“噪声加得越多，SNR 线性下降”。
  • 把 INL_LSB 改成 2.0：观察 SFDR/THD 和码密度；确认 INL 是“形状”，不是随机噪声。
  • 把 JITTER_RMS_S 改成 1 ps，信号频率改到 10 MHz：观察抖动从“可忽略”变成“主导”。这是理解 4.5 节公式的最好实验。
  • 把 ADC_LATENCY 改成 0/5：确认 scoreboard 只改一个参数就能对齐；如果对不齐，说明它按绝对时间而不是按 valid 计数。
    • 一个容易被忽略的复现条件

    噪声实验必须固定 SEED，并且保证随机数调用次数不随参数变化。例如，如果把 JITTER_RMS_S 从 0 改成非零，会多调用一次 gauss()，后续噪声序列整体偏移；这时 SNR 的微小变化不能全部归因于抖动。要做干净的 A/B 对比，要么固定调用次数，要么用独立的随机流/种子。

    6把模型放进数字验证环境

    模型能跑通，不等于能交付。数字验证环境关心的是：可重复的激励、正确的采样、可解释的失败、可度量的覆盖。下面给出一套最小但完整的集成方式；即使团队不用 UVM，这个结构也可以映射到 Python/ Cocotb 或自研 testbench。

    6.1 Driver：在正确的沿更新模拟输入

    模拟输入是 real，但它仍然受离散事件调度约束。Driver 最常见的错误，是在 posedge clk 的同一个 Active 区改 vin_p，而 DUT 也在同一个沿采样；谁先执行取决于仿真器，结果不可复现。正确做法是：

    • 用 negedge clk 驱动，给 DUT 半个周期建立；或
    • 用 clocking block，把驱动偏置到采样沿之后；或
    • 用连续波形源（always #...）并以足够小的时间步逼近，但这对性能不利，且仍需保证采样沿的值可预测。

    对相干 FFT，推荐“按样本索引”而不是“按绝对时间”生成正弦：x[n] = Asin(2πMn/N)。这样即使时钟有抖动、仿真起点不同，样本序列仍然严格相干；相位偏移只影响 FFT 的相位，不影响幅度和 SNR。

    6.2 Monitor 与 Scoreboard：按 valid 对齐，不按时间对齐

    Monitor 在 negedge 采样，把 {code, sat, gain, timestamp, sample_index} 打包成 transaction。Scoreboard 维护一个按“有效样本序号”索引的期望队列：

    snippet/scoreboard.svsystemverilog
    class afe_scoreboard extends uvm_scoreboard;
  `uvm_component_utils(afe_scoreboard)
  afe_txn expected[$];
  int unsigned checked, failed;

  // Called by the reference model / predictor.
  function void push_expected(afe_txn t);
    expected.push_back(t);
  endfunction

  // Called by the monitor when a valid output appears.
  function void check(afe_txn got);
    afe_txn exp;
    if (expected.size() == 0) begin
      `uvm_error("AFE_SB", "unexpected valid output")
      return;
    end
    exp = expected.pop_front();
    checked++;
    if (got.code !== exp.code) begin
      failed++;
      `uvm_error("AFE_SB", $sformatf(
        "code mismatch: got %0d exp %0d (sample %0d, seed %0d)",
        got.code, exp.code, got.sample_id, exp.seed))
    end
  endfunction
endclass

    三个细节决定 scoreboard 是否可靠：

    1. latency 是参数，不是魔法数。期望队列的深度等于 LAT；如果 DUT 支持 backpressure，还要加一个“已发出但未接收”的计数。
    2. 模拟噪声下不要逐码精确比较。有噪声时，相邻样本的码可能差 ±1 LSB；逐码比较会产生大量假失败。正确做法是：无噪声定向测试逐码精确；有噪声回归比较统计指标（SNR/ENOB/直方图）。
    3. 失败要能重放。记录 seed、gain、输入频率/幅度、采样序号和期望/实际码；只报“mismatch at 12345 ns”无法定位。

    SNR/SINAD相干单音 + FFT；固定 seed；N ≥ 4096≥ 预算值，且重复运行 ±0.2 dB
    THD/SFDR单音/双音；看谐波 bin 和最大杂散≤ 预算；无工艺相关异常峰
    建立阶跃/增益切换；测到 0.5 LSB 的时间≤ 系统分配的时间窗
    码密度/DNL慢斜坡 + 直方图；或 LUT 模型无缺失码；DNL 在规格内

    FFT 的设置必须和模型/激励一致：相干采样用矩形窗；非相干采样用 Hann/Blackman-Harris 窗并做泄漏修正；不要把窗函数的能量损失算进 SNR。示例的 Python 脚本只实现了相干路径，并在注释里明确这一点。

    6.4 覆盖率：覆盖“模拟条件”，而不只是数字码

    只覆盖 adc_data 的 bin 是不够的：同样的码可能来自不同增益、不同输入幅度、不同噪声/温度条件。建议至少交叉：

    • 输入幅度 × 增益档（覆盖小信号、满量程、削顶）。
    • 输入频率 × AAF 截止频率（覆盖通带、过渡带、混叠）。
    • 噪声密度 / 抖动 / INL 开关（覆盖损伤组合）。
    • 复位/掉电/增益切换与有效样本的时序关系。

    对 real 的覆盖，先映射成整数 bin。例如把输入幅度按满量程百分比分成 8 档，把频率按 fc/fs 分成 6 档，再对整数 bin 做 coverpoint/cross。这样既跨工具可移植，也更容易在报告里解释。

    6.6 与 Verilog-AMS / SPICE / DPI 的边界

    纯 SV RNM 不是唯一的混合信号方案。实际项目常见的组合是：

    • RNM 做 SoC 回归：AFE 数字接口、增益/校准、码流、DSP 验证；速度快，可约束随机。
    • Verilog-AMS/AMS Designer 做模块级：需要连续时间反馈、开关电容电荷分享、真实 wreal 连接时；精度高，速度慢。
    • SPICE 做签核/锚点：DC、AC、瞬态、噪声、corner；为 RNM 提供系数和验收容差。
    • DPI/C/Python 做重计算：FFT、自适应算法、复杂噪声整形；注意跨语言调用开销，不要在每个样本上调 DPI。

    wreal 是 Verilog-AMS 的实数 net，不是纯 SystemVerilog 的标准类型。用 AMS 时可以用 wreal 连接多个模型并定义 resolution；用纯 SV 时，老老实实用 var real 端口/接口，不要假设所有工具都支持 wreal。两条路线的模型方程可以复用，但端口/连接语义要分开。

    6.7 与 SPICE / bench 的对标

    交付前至少做四类对标，并记录容差：

    1. DC：输入从 0 扫到 VREF，比较输出码/电压；检查共模、失调、钳位。
    2. AC：在 0.01·fc 到 10·fc 扫频，比较增益/相位；重点看 fc、peaking、带外抑制。
    3. 瞬态：小阶跃、大阶跃、增益切换；比较过冲、建立、恢复。
    4. 噪声/失真：输入接地测噪声 RMS/PSD；单音/双音测 SNR/THD/IM3；比较时统一带宽和参考点。

    对标不是“看起来一样”，而是给出频点/时间点的数值表和容差。例如“DC 增益 ±0.2%”“fc ±3%”“0.5 LSB 建立 ±10%”“SNR ±0.5 dB”。超过容差时，先查参考点/带宽/窗函数，再怀疑模型。

    7性能、调试与常见陷阱

    行为模型的速度不是“免费”的。每个 real 运算、每个事件、每次文件写入都要花时间。一个在 1 MS/s 下看起来很快的模型，跑到 100 MS/s × 数百万样本时可能完全不可用。优化之前，先量清楚时间花在哪里。

    7.1 性能清单

  • 在采样率上算，不要在每个 delta 上算。用 posedge clk 驱动状态；不要用 always @(vin) 跟随连续波形。事件数从“每个数值变化”降到“每个样本”。
  • 预计算系数。把 $exp/$tan/$sqrt 放进 localparam 或 initial；热循环里只做乘加。
  • 关闭不用的损伤。用参数条件生成随机数/多项式；不要在关闭时仍然调用 gauss()，否则既慢又改变随机序列。
  • 不要逐样本 $display。文件/终端 I/O 往往比数学运算慢一个数量级；用批量 CSV 或只在失败时打印。
  • 谨慎使用 shortreal。32-bit 浮点能省内存/带宽，但深零极点/高动态范围下可能引入可见误差；先用同一测试对比 real 与 shortreal 的 SNR/建立。
  • 把重计算移出热循环。FFT、自适应滤波、复杂噪声整形可以放到 Python/C/DPI，按 block 调用；不要每个样本跨语言。
  • 用 plusarg 控制调试。默认关闭 debug 打印/波形转储；需要时用 +debug=1 打开，避免拖慢全回归。

    7.3 一个可执行的调试顺序

  • 静态检查：单位、位宽、符号、端口方向、复位覆盖。先让编译器 -Wall 干净（除了“real 不可综合”的预期警告）。
  • DC 工作点：零输入、共模 0.9 V，逐级看 dbg_lna/aaf/pga 是否都在 0.9 V；ADC 码是否 2048。
  • 小阶跃：1 mV 阶跃，检查增益和极性；大阶跃检查钳位和 sat。
  • 单音：先关噪声/INL，看量化噪底和谐波；再逐项打开，确认每一项只改变预期的指标。
  • 噪声：输入接地，测输出 RMS 和 PSD；与 NSD·√ENBW 对比。注意别把量化噪声算进“热噪声”。
  • 时序：用脉冲/斜坡标记样本，测 LAT、吞吐、enable 清零/恢复；检查复位后第一个 valid。
  • 回归：固定 seed，跑增益/幅度/频率矩阵；记录失败样本和参数哈希。

    • 8交付清单与参考

    8.1 模型交付的 Definition of Done

  • 契约：端口/单位/范围、采样沿、LAT、复位/掉电、控制更新、seed、精度容差、排除项。没有契约的模型不进入 DV 环境。
  • 代码：参数化、可关闭损伤、无未初始化状态、无逐样本调试打印、编译警告已审阅。至少通过一个 lint 和一个不同仿真器的 smoke test。
  • 自检：DC、阶跃、单音、噪声、饱和、复位、延迟各一个测试；失败可复现。测试与模型同目录、同版本。
  • 对标：SPICE/bench 的 DC/AC/瞬态/噪声表格与容差；关键系数有出处。“看起来像”不算对标。
  • 指标：SNR/SINAD/THD/SFDR/ENOB、建立时间、功耗（如需要）的基线数值与测试条件。让算法组能直接引用，而不是自己重跑。
  • 性能：典型回归的仿真时间/样本数；已知瓶颈和关闭 debug 的方法。跑不完的模型等于不可用。
  • 版本：模型版本、参数哈希、seed、变更记录；与数字 RTL 版本的对应关系。失败时能回答“是模型变了还是 RTL 变了”。
